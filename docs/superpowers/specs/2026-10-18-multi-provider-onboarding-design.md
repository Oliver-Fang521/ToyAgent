# 多服务商模型选择与首次使用引导设计

日期：2026-10-18（America/Chicago）

状态：用户于 2026-10-18 批准修订版，并授权使用已提供的对应凭据进行有界测试；进入实现计划审阅。

## 1. 用户目标和本轮边界

用户希望把现有 toy_multi_agent 变成值得向其他人推荐的研究助手，而不是只有界面的演示。
首批仅接入 OpenAI、DeepSeek 官方服务，允许用户自己选模型和配置自己的 Key。
按用户最新决定移除 Anthropic，不保留对应模型、凭据槽位或适配器实现任务。
未登录、未配置 Key、Key 失效时，主动引导到对应界面，完成后回到原问题。
开发者必须亲自操作网页、观察输出和日志，定位失败、优化并回归，而不是仅宣称接口接通。

本轮交付是多服务商执行链和引导闭环，不包含任意中转地址、订阅计费、自动跨服务商路由、
新增通用代码沙箱、永久文件知识库、云部署或“已达到主流产品水平”的未经验证声明。
产品后续优化以记录的任务表现为依据，不能把无限迭代理解为无限付费调用。

## 2. 方案和取舍

采用两家官方直连、独立适配器、统一内部请求/响应及工具协议。
不采用第三方聚合网关，以免增加 Key 接收方和额外计费、留存及兼容风险。
不把所有服务商简单套进现有 OpenAI 客户端：表面兼容不保证工具、结构化输出或推理参数兼容。

保留现有 LangGraph Plan → Act → Verify → Submit 和语义分流。一次任务的分流、规划、
专家、验证及提交使用用户所选服务商和模型，不暗中调用站长 Key 或另一家模型。
原有 CLI 和历史 GAIA 结果不改写、不重跑、不借用来证明新模型效果。

## 3. 服务商目录和模型能力

增加服务端 ProviderRegistry / ModelCatalog，浏览器只能提交目录中的 provider/model 标识。
官方端点固定为 OpenAI 的 api.openai.com 和 DeepSeek 的 api.deepseek.com。
浏览器不能覆盖 base_url、认证头、组织或代理；禁止携带凭据跟随重定向。
API 路径前缀由适配器确定，不由浏览器拼接。

首批目录：

| 服务商 | 模型 ID | 初始依据 |
| --- | --- | --- |
| OpenAI | gpt-6.1-sol | 当前项目已使用，保留现有 low 默认偏好 |
| DeepSeek | deepseek-flash、deepseek-v4-pro | 本次获取的官方 Responses 文档；尚未用本项目实测 |

目录是应用支持范围，不代表每个用户账号都有权限。每项记录 provider、model、display_name、
支持的文本/图片/结构化输出/函数调用/托管搜索/托管代码执行/音频能力、允许的推理参数、
文档核对日期及本项目实测状态。新模型必须更新目录及协议测试，不能仅因 /models 返回就启用。
OpenAI 保留现有默认选择；首次选择其他服务商时要求用户明确选模型，不自动选更贵的模型。
不支持的推理参数不发送；两家的 low 不假定具有相同含义。界面只呈现已映射的参数。

实测状态分为 documented、contract_tested、live_verified；只对对应测试覆盖范围作声明。
下拉菜单显示能力限制和“尚未实测”，不编造速度、价格、质量或账号可用性。

## 4. 适配器和工具执行

OpenAI 保留 Responses 适配器；DeepSeek 使用其官方 Responses 兼容接口的独立适配器。
共享消息转换辅助函数可以复用，但不能共享服务商密钥。

两个适配器遵守现有 ModelProvider.complete 边界，统一正文、工具调用、引用、终态和 usage。
本地 Pydantic/JSON schema 校验始终保留；服务商有结构化输出并不替代本地校验。
保留现有有界格式修复，不增加无限重试。推理块、原始响应和请求体不得进入公开日志。
涉及工具的内部连续调用需要服务商协议状态时，仅在该次执行内存中处理，不向前端披露。

所有工具都由服务端能力清单和角色 allowlist 双重约束，不能依靠提示词禁止危险工具。
模型生成的工具参数仍是未经信任的数据，沿用路径、网络、大小、次数和超时限制。
DeepSeek 不发送 OpenAI 专有托管工具；函数工具和上下文历史由应用管理，预算由本地计数强制执行。
任何工具必须有真实执行结果才能记为完成、生成证据或通过验证；不能把模型文字当工具输出。

共同基础能力：普通文本、语义分流、规划与验证、受限网页读取、TXT/CSV/PDF/XLSX 本地提取。
搜索可使用用户配置的独立搜索服务，界面明确显示搜索服务的接收方；没有搜索能力时不宣称完成全网搜索。
图片、托管搜索、托管计算、音频按具体模型和适配器能力启用。
OpenAI 继续保留现有已实现的托管路径；DeepSeek 不借用 OpenAI 执行 Python 或转录音频。
缺少所需能力时返回 capability_unavailable，
保留问题并建议用户主动换模型，不能不经同意转发文件。新通用沙箱另立项目。
扫描 PDF 没有可提取文本时，明确说明当前限制，不声称已经读取全部内容。

## 5. 凭据边界和迁移

凭据槽位改为 openai、deepseek、serper、serpapi，保持 owner 隔离、AES-GCM、
明确保存同意、掩码状态、替换/删除/轮换、无明文导出等现有约束。
加密附加认证数据必须绑定 owner、provider 和版本；不能直接把旧密文改标签。

旧 model 槽位保留为 legacy，不能自动认定属于任意一家。设置页显示“旧配置待确认”，
由用户确认归属 OpenAI 并同意迁移后，在服务端解密并以新 AAD 重加密，事务中保存新槽位、
删除旧槽位。不返回明文；中断不丢失唯一副本。非官方历史端点不自动迁移或继续发送。
迁移不删除对话/任务/附件；历史任务标为 legacy，不能伪造原先使用的服务商。

临时引用绑定 owner、provider、generation 和到期时间。沿用 30 分钟会话及全局上限；
第一版每人仅一份活动临时材料，明确提示新建临时材料会替换旧材料，UI 不保留失效句柄。
修改、迁移或删除任一凭据继续保守地失效该用户所有临时引用，并取消其排队/活动任务。
实际 dispatch 再核验引用所属 provider 与任务一致；任何不一致都在网络请求之前拒绝。
运行中禁止换模型/服务商；失败不能自动换另一家 Key、模型或 endpoint 重试。
Key 永不进入问题、草稿、任务表、URL、浏览器持久化、日志、分析事件或错误响应。
只有用户明确填写的独立搜索凭据可以注入工具进程；不注入其他模型服务商的 Key。

## 6. API 和数据契约

- 新增只读模型目录供未登录界面显示；前端 /api/agent/model-catalog 允许匿名，仅返回静态
  模型/能力目录，不读取凭据或账号状态、不调用服务商。其后端 /v1/model-catalog 仍要求
  服务端 token，但仅该 GET 不要求用户身份；其他 /v1 路由的认证边界不放宽。
- InteractiveRequest 新增必填 provider、model；拒绝额外端点或认证字段。
- 客户端执行顺序：认证 → 目录和能力校验 → 同参数幂等查询 → 对话服务商约束 → 凭据解析
  → 原有活动/队列限制 → 接纳任务。相同幂等键但不同 provider/model 返回冲突。
- 任务表增加 provider/model；新任务必须记录实际选择。响应、诊断及结果元信息带同一快照。
- 对话增加绑定 provider；跨 provider 的 task 请求即使篡改前端也拒绝，不会读取旧对话 history。
- 同一服务商换模型可在下一任务应用，已有结果保留各自实际模型；未完成任务不可改变快照。
- Credential API / sessions 显式指定 provider，校验 owner/provider/ref 一致；状态仅给掩码和端点。
- 模型权限、额度、认证、参数/格式、工具、超时和验证失败保留安全分类，扩展 provider/model
  和能力错误码；不把所有失败折叠为“网络错误”。Key 保存成功不等于模型已验证。
- 不恢复每小时任务提交上限；每人 1 活动任务、全局 2 执行/10 排队、500 秒和工具预算保持。

## 7. 登录、配置和继续使用

提交入口使用统一状态机：editing → sign_in_required / key_required → ready → explicit_submit。
没有账号先进入现有登录路由；已登录但缺少所选 Key，直接打开对应服务商的设置页并聚焦 Key 输入。
设置页显示官方获取 Key 链接、接收域名、费用由谁承担、默认不勾选保存，并支持返回原问题。
401/会话过期时重新登录；Key 缺失/过期/撤销/认证失败则进入对应配置。额度不足不误导用户反复换 Key。
完成登录或保存 Key 后显示“继续发送”；绝不自动提交、重复上传或执行付费验证。
需要测试连接时有独立说明和用户操作，不在输入、保存、切换下拉菜单时偷偷生成模型请求。

登录跳转之前，只把问题正文和 provider/model 草稿临时存入同源 sessionStorage，不包含 Key、
句柄或文件内容；提示本标签页临时保存草稿，提供“不保留并登录”。15 分钟过期、一次性恢复，
关闭标签页、主动退出登录或完成发送后清除。存储不可用时提示复制问题再登录，不静默丢失。
恢复后用户可编辑并确认发送，不在 URL 中传问题，不跨用户自动发送或恢复历史会话 ID。
真实附件不写入浏览器持久化；必须跳转时提示回来后重新选择文件；同页 Key 弹窗保留内存中的附件。

## 8. 切换服务商与 UI

输入区上方展示“服务商 / 模型”和适用能力，选项在手机和键盘操作下可用。
切换到其他服务商默认新建对话，只保留当前尚未发送的草稿；原对话历史仍可在侧边栏查看。
这一版不提供跨服务商继续旧对话功能，以免不知情地转发历史内容；后续如增加须单独明确确认。
已有对话明确显示绑定服务商；不要用最新下拉选项重标历史答案。模型/服务商信息可复制排查。
空状态给出登录/配置的下一步，不是不可操作的发送按钮；认证和凭据仍由服务端强制验证。
错误卡提供明确下一步（登录、配置、调整任务、换支持该能力的模型），不自动付费重试。
回答和来源保持文本安全渲染；这一版不安装未审查的 HTML/Markdown 引擎来实现外观优化。

## 9. 自测、效果标准和持续改进

维护 15 个固定、非 GAIA 私有数据的产品验收用例：中英问候、翻译、保真改写、多轮追问、
信息不足澄清、概念解释、带来源查证、计算、TXT、CSV、PDF、XLSX、模型认证失败、
不支持的能力、取消/重开。每项列出明确的正确条件与不应出现的行为。

离线层：两家协议夹具、格式/截断/拒绝/工具循环、usage、能力门禁、隐私与超时；
加密迁移断点、跨 owner/provider 引用、并发和失效；重复提交不能重复收费。
UI 层：未登录 → 登录、无 Key → 对应设置、完成后恢复草稿且不自动发送、切换提供商新对话、
刷新/返回/存储禁用/Key 过期、移动端及键盘、错误操作恢复。模拟测试明确标记，不冒充真实登录。

真实调用第一轮最多 6 个任务、每家最多 3 个，优先覆盖直接回答、多轮/澄清及带证据的研究/文件。
只使用用户主动配置并允许用于测试的对应官方凭据，不读取其他软件的 Key，不把 Key 放到对话中。
缺少某家凭据时完成其离线和模拟 UI 验证，并把真实调用标为未验证，要求用户在设置页配置，不能绕过。
OpenAI 优先沿用现有网页加密保存的配置，按迁移确认流程处理，不从聊天记录或其他软件提取 Key。
聊天中披露的凭据不抄入代码、文档、命令参数、日志或测试夹具，并提醒撤销和更换。
用户已明确再次授权使用给出的 DeepSeek 凭据测试；允许通过不回显的标准输入，仅在测试进程
内存和 owner/provider 绑定的临时会话中使用，不加密保存为长期凭据，不操作其他软件的密钥。
测试许可仅适用于对应官方端点，不构成上传凭据到其他服务或部署平台的许可。
后续付费回归若超出本轮限额，先提出具体任务数及所需授权；不得以“持续优化”为由无限调用。

逐次记录测试用例、provider/model、实际选路、完成/失败、墙钟耗时、token、工具次数及人工质量判定。
成本不确定时只报告 token/工具使用，不编造美元费用。保真、证据相关性、来源可达和任务完成是效果标准，
不能只判断 HTTP 200。错误必须可解释、下一步可执行；不能出现假来源、假工具执行或跨家静默重试。
失败 → 定位 → 回归测试 → 修复 → 原例复测；同一失败反复出现时追根因，不靠重试次数获得好看结果。

可交付本轮的条件：全部离线/现有回归通过；UI 状态机验收通过；已取得凭据的服务商真实任务全部通过。
只完成少量 smoke tests 时不能称所有 15 项都做过真实验收；按服务商列出真实覆盖和未覆盖项。
值得公开推广仍需真实 HTTPS 登录、部署授权、独立安全复核、日志和快照留存/删除验证，
以及更完整、可复现的实际任务效果评估。测试报告必须区分“本轮实现完成”和“公网发布通过”。

## 10. 实施边界和官方依据

按目录/凭据迁移、适配器/能力、任务隔离、引导 UI、自测与报告划分实现步骤。
保留当前未提交的语义分流改动；在现有 managed worktree 内进行，不移动分支或覆盖用户文件。
延续本会话既有不分派实现/审查子代理的约束；实现者自查不代替独立的上线安全复核。
本文审阅通过后编写可执行计划，再经用户选择执行方式。本文提交不等于产品代码已实现。

官方资料核对于 2026-10-18：

- [OpenAI Docs: Using tools](https://developers.openai.com/api/docs/guides/tools)：
  区分应用函数和托管工具，不能把一个模型接口视作所有工具的通用运行环境。
- [DeepSeek: Responses compatibility](https://api-docs.deepseek.com/guides/responses_api/)：
  参数/工具存在部分支持或忽略的情况；本地必须强制预算、能力和真实执行检查，不能仅换 base_url。

模型和能力会变化；实现时再次核对目录项的官方文档及实际协议测试，不把文档例子当作账号访问授权。
