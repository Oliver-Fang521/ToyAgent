# ToyAgent：简洁记忆管理、完整模型选择与 DeepSeek 搜索

日期：2026-10-19。阶段：设计稿，等待用户审阅；不是实现完成报告。

## 1. 用户目标与边界

用户要一个接近 Claude 交互习惯、安静简洁的真实应用，而不是后台管理表单：

- 记忆页面只突出开启/暂停、查找、阅读、新增、编辑和删除。
- 下拉菜单有轻量动画，中文和英文同步，支持键盘与减少动态效果。
- OpenAI、DeepSeek 不应永远只有三个固定选项；展示当前官方文本/推理模型，
  让兼容且账户可访问的模型可选，真实传递各模型支持的 reasoning 配置。
- 将 DeepSeek 官方网页搜索作为 Agent 工具接入研究流程，返回可追溯来源。

保留 ToyAgent 品牌和已确认的暖深灰聊天布局，不复制 Claude 标识或专属素材。
不修改用户已有记忆，不回填历史，不删除聊天，不改变默认记忆与账户隔离规则。
不自动部署、合并 PR 或使用站长 Key。图像生成、语音、嵌入、审核等专用模型
不伪装成可执行当前聊天/研究工作流的模型。

这是跨 UI、请求契约、运行时、工具和存储的架构性改动。用户对方向的确认只允许
形成这份设计；书面设计通过后再写实施计划，计划通过后实施。

## 2. 已核实的现状与来源

### 代码现状

- `interactive/catalog.py` 只有 GPT-6.1 Sol、DeepSeek Flash、DeepSeek V4 Pro。
- `InteractiveRequest` 不接收推理档位；`InteractiveConfig` 将档位限制为 `low`。
- `UserRuntime` 从固定 profile 构造配置，没有使用用户推理选择。
- `DeepSeekResponsesProvider` 会删除 reasoning 参数，并拒绝非 function 工具。
- DeepSeek 工具策略目前依赖另配的 Serper/SerpAPI 才开放 `web_search`。
- 记忆使用加密 owner-scoped 存储、字段/类别闭集、修订号和删除屏障；这些不重做。

### 官方资料

核对日期同上。以下资料是能力依据，不等于当前用户账户的实际访问权限：

- [OpenAI 模型目录](https://developers.openai.com/api/docs/models)：当前模型与历史型号。
- [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)：支持
  low/medium/high/xhigh/max，不支持 none/minimal；工具调用使用 Responses API。
- [DeepSeek 模型元数据](https://api-docs.deepseek.com/api/list-models/)：包含展示名、
  模态和 effort 档位。示例的 `deepseek-flash` 展示名为 DeepSeek-V4.1-Flash，
  不能据此虚构一个 `deepseek-v4.1-flash` API ID。
- [DeepSeek 推理模式](https://api-docs.deepseek.com/guides/thinking_mode/)：
  Responses 使用 reasoning.effort；none 关闭推理，规范档位为 low/high/max。
- [DeepSeek Search / Fetch](https://api-docs.deepseek.com/guides/search/)：
  独立 JSON API，使用 DeepSeek Bearer Key；Search 和 Fetch 有独立调用计费。
- [Search 请求协议](https://api-docs.deepseek.com/api/search/)：query 为 1–128 个
  Unicode 字符，count 为 1–50，结果包含 URL、标题及摘要等字段。

实施时逐模型复核能力，不能将一个型号的档位或工具能力复制到全系列。

## 3. 记忆管理：以内容为中心

### 默认页面

标题「我的记忆」，右侧一个开启/暂停开关。下方为搜索框和「新增记忆」按钮，
主体直接显示记忆正文。类别、字段 ID、版本号、服务商、来源和时间不再逐条堆放。
需要时在编辑页的「高级设置/详情」查看。每条右侧「⋯」菜单提供编辑、删除；
长正文允许展开，不因截断而丢失可读内容。

暂停时只显示一条短状态「已暂停」，保留列表与人工管理。加载中不假装已开启；
错误只显示一条简短原因与重试操作。清空全部放进页面的更多菜单，不占主要位置。
空状态仅「还没有记忆」和新增入口，不显示一段政策说明。

### 搜索与列表快照

搜索仅针对当前账户的已保存内容，不调用模型，也不把搜索词写进 URL 或日志。
新增受保护的列表快照读取接口：在同一仓库锁/事务内取得 generation 和最多 200 条
面向该账户的 MemoryView（不是公共接口）。保留旧分页接口兼容性，新页面对快照在内存中过滤；不把正文放进
localStorage/sessionStorage。关闭页面、切换账户或撤销会清理 UI 快照和编辑状态。
返回值不含密文、canonical key、Key、来源原始片段或其他账户信息，使用 no-store。

### 新增、编辑和删除

新增/编辑使用独立弹窗，主区域只有「记忆类型」和「内容」。一个分组类型菜单
替代两个类别/字段下拉框，映射到现有合法 category/facet；当前类型始终可见，
不隐藏分类，也不凭空用模型猜测类型。项目/决定类型才显示名称输入框。

服务商共享、有效期及记录详情收进「高级设置」。跨服务商仍默认不共享，
没有勾选的服务商不能收到正文。保持人工编辑优先、修订号 CAS 和 409 草稿保护。

删除时才解释不能直接撤销和自动采集屏障；清空全部另行确认。用户不应在每次
打开列表时读一遍删除、备份、收费和模型权限说明。私密性与费用细节放入可展开的
帮助区；不能删除必要的 Key 保存同意或在实际共享/计费边界隐藏重要信息。
人工恢复被删除字段时仅就地提示「保存后恢复此字段采集」，沿用现有恢复语义。

修改记忆仍会撤销旧 generation 的活动任务，不自动付费重发。若有活动任务，
在保存/暂停前做一次明确的「此操作会停止当前任务」确认，不永久占用页面。
保留每条回答不显示记忆更新状态的既有要求。

## 4. 统一菜单与动效

抽取共享 Popover/Select 行为，应用于记忆类型、服务商、有效期预设、模型、推理
和界面语言，避免每个页面再写一套。日期自定义输入保持可访问的日期控件。

- 打开：约 160–180ms，淡入及 4–6px 位移；关闭约 120ms。
- 箭头旋转、选中背景过渡不阻塞输入；不使用夸张弹跳或长等待。
- 小屏自动限宽、翻转/避让，长列表内部滚动，不横向撑破窗口。
- Enter/Space 打开，方向键移动，Enter 确认，Esc 先关子菜单，再关弹窗。
- 点击外部关闭；关闭后回到触发按钮。隐藏选项不可被 Tab 进入。
- 遵守 prefers-reduced-motion，保持标签、选中状态和至少 44px 的主要触控区域。

中英切换只改界面，不改记忆正文、聊天文本、文件名、模型 ID、工具参数或回答语言。

## 5. 模型目录：完整展示，按真实能力启用

### 目录结构

采用「官方能力注册表 + 当前账户发现」双层目录，而不是任意字符串透传，
也不是只把三项换成几十个硬编码名字。

1. 官方注册表记录 API ID、展示名、协议、输入模态、工具/结构化输出能力、
   推理档位、默认值、证据链接、核对时间与适配状态。
2. 使用用户已配置的对应服务商 Key 按需读取官方模型列表，确认账户可见 ID。
   不用运营者 Key，不在浏览器暴露 Key、组织字段或原始响应。
3. 账户发现缓存按 owner/provider/credential generation 隔离，TTL 15 分钟；
   换 Key、删除 Key 或退出账户立即失效。没有 Key 仍可浏览官方目录，选用时走
   原有登录/Key 引导；读取列表不会触发模型生成请求。
4. 未登录的公共目录不含账户信息。账户刷新接口单独鉴权且仅接受服务商枚举，
   不接受自定义 base URL。刷新失败保留已核验的静态目录，不宣称它是实时权限结果。

### 覆盖范围与显示

首轮目录应覆盖官方索引中当前可用于文本对话/推理的系列，而不是只推荐三款。
OpenAI 包括 GPT-6 Astra、GPT-6.1 Sol、GPT-6 Sol、GPT-6 Luna，GPT-5.6
Sol/Terra/Luna，GPT-5.5、GPT-5.4 及其实际可用变体，并继续核验 GPT-5.x、
GPT-4.1、GPT-4o 和 o 系列的兼容条目。实施时从官方索引形成逐 ID 覆盖表，
记录启用或禁用原因；不把目录中的废弃模型当成当前可运行模型。

DeepSeek 使用官方 ID 与元数据，显示实际版本名；当前文档示例至少包含
`deepseek-flash`（DeepSeek-V4.1-Flash）和 `deepseek-v4-pro`。新版本通过
同一发现/核验流程更新，不编造不存在的版本 ID，不把旧聊天产品名称当新 API。

模型菜单按服务商/系列分组，提供搜索与「显示历史型号」选项。常用型号靠前，
其他条目仍可搜索。未知兼容性或专用工作流未适配的型号显示禁用原因，不假装可选。
只要兼容当前文本/研究调用路径且账户可访问就应可选，不因它不是默认推荐而隐藏。
图像生成、转录、嵌入等不进入这个文本模型菜单；它们仍可作为独立工具能力存在。

API 列表可见不等于实际请求一定有权限；400/401/403/404 返回清晰安全原因，
不会擅自换成其他昂贵型号或自动重发。模型变更不自动跨服务商发送旧历史。

### reasoning 贯穿调用链

请求新增可选 reasoning_effort；缺省兼容旧客户端，GPT-6.1 Sol 默认保持 low。
前端只显示该 profile 的合法档位。DeepSeek 显示关闭/low/high/max，不显示会
映射到相同效果的 medium/xhigh 等重复别名；OpenAI 则严格按具体型号提供选项。
无 reasoning 参数的型号不显示假档位。

执行链必须完整：选择器 → 请求体 → Pydantic profile 校验 → 幂等指纹 → 排队
记录/历史 → UserRuntime 配置 → 路由、直接回答、研究角色、验证与可选记忆整理
的 provider 请求。DeepSeek adapter 不再无条件删除 reasoning；非推理模型则
省略不支持的字段。结构化输出、工具和附件策略也按具体 profile 校验。

提交时冻结实际 provider/model/effort 和能力版本；重连、重启和查看历史不读取
用户后来修改的选择来替换旧任务参数。别名仍可能由上游更新，不能承诺固定权重。
旧记录显示未记录档位，不能回填成用户从未选择过的值。

服务端拒绝非法组合，不能静默降档。500 秒总时限、工具预算和撤销屏障保留；
高推理档位不自动延长超时或触发新付费任务。选择高计算档位时才给一条短提示，
不在全部菜单项下反复显示小字。

## 6. DeepSeek 搜索作为工具

### 选择方案

使用官方独立 Search / Fetch API 包装成现有工具，优先于把 Pro 专属的托管
web_search 塞进所有型号。这样 Flash/Pro 均能在本地执行相同的工具协议，
也便于控制来源、调用预算与错误。保留现有 Serper/SerpAPI 适配，不再强制用户
为了 DeepSeek 搜索另外配置它们。

DeepSeek 模型默认使用本账户 DeepSeek Key 进行 DeepSeek Search；OpenAI 模型
默认保持 OpenAI 搜索路径。这一轮不默认跨服务商借用搜索 Key 或发送查询。
没有配置的服务不启用，不能退回运营者密钥或暗中调用另一家模型。

### 工具与适配点

- 增加 DeepSeekSearchProvider，接入 SearchProvider/有界调用链。
- `web_search` 内部请求 `https://api.deepseek.com/v1/tools/search`。
- `read_webpage` 可对已验证的公开 URL 使用 `/v1/tools/fetch`；无法抓取时遵守
  目标访问政策，不绕过登录、付费墙或安全拒绝。
- 更新工具可用性策略、MCP 显式运行环境和安全 provider 枚举，避免新 provider
  被裁剪掉、工具不可见或进度误标为旧服务。
- Key 仅从该 owner 的执行凭据引用解析，发往固定官方 HTTPS 域名；关闭重定向与
  环境代理继承，不将 Key 放在工具参数、URL、记忆、结果、notebook 或日志。

### 输入、证据、安全和费用

query 最多 128 个 Unicode 字符，默认返回 5 条结果。超过限制返回可修正的工具
输入错误，不能静默截断查询。默认不发送 ori_question、用户 IP、本地化地址、
完整聊天历史或额外记忆上下文；由 Agent 按需生成最小搜索词。拦截已知凭据泄漏。

只向 Fetch 发送经过公共 URL/凭据/协议/私网策略校验的地址，不执行网页中的指令。
内容作为不可信外部证据，经过长度/结果数限制后进入 notebook 和验证流程，
不能变成用户记忆，也不能覆盖系统规则。来源保持 URL、标题、摘要和检索时间；
模型输出的结论必须可追溯，不能伪造引用。

Search/Fetch 共享现有任务截止时间、调用预算、取消和记忆撤销屏障。401/402/403
明确区分鉴权、余额与拒绝；不反复重试。408/429/5xx 才按有界策略重试；如果
额外配置并允许其他搜索服务，才允许受控回退并记录实际 provider。空结果是合法
结果，不伪装成网络故障，不无限切换服务补搜。

前端进度显示「网页搜索 · DeepSeek」「读取网页 · DeepSeek」。失败明确到工具名、
服务商、安全错误码和可操作建议，区分模型调用失败；不展示原始响应体或 secret。
成功搜索/抓取次数单独记录，不能伪装为模型 token 用量，也不承诺永久免费。
价格链接放入可展开详情，费用以官方计费及实际账户为准。

## 7. 兼容性、测试与验收

### 兼容性

保留旧 API 与已保存数据；新增运行字段使用可回滚迁移，不重写普通聊天/记忆正文。
完整保留 account scope、provider 隔离、临时会话、保存同意、generation 撤销、
删除屏障、任务取消和“不自动付费重试”的既有约束。

### 自动测试

- 记忆列表快照 owner 隔离、200 条边界、generation 一致性、无永久浏览器存储。
- 搜索、类型菜单、编辑 CAS/409 草稿、暂停、恢复、删除确认和删除后不自动学回。
- 每个注册模型的能力/合法档位、未知型号、过期目录、账户发现隔离及 Key 轮换。
- 请求到真实 SDK 边界的参数契约；更换档位改变幂等指纹；历史回显不可漂移。
- DeepSeek Search/Fetch 请求形状、128 字符边界、结果解析、URL 安全、凭据脱敏、
  空结果、401/402/403/429/5xx、超时/取消/撤销和工具预算。
- 中英切换仅影响 UI；对话、文件名和记忆即使等于 UI 文案也保持原样。

### 浏览器验收

在实际构建上验证桌面、390px 和 320px，记录真实 innerWidth/scrollWidth，
避免将未生效的视口覆盖当手机通过。测试键盘、Esc 分层退出、焦点回归、减少动画，
以及模型搜索回车不误提交。先用隔离账户/临时数据库/假执行器完成破坏性与提交测试，
不改用户真实记忆/Key。验收新列表不再堆管理字段和说明段落。

真实模型/搜索烟测另行约定次数和费用上限，仅使用用户已提供且授权的对应 Key；
离线/合成测试不算真实服务效果。不得用一次模型成功代表全部型号都已实测。

完成条件：核心 UI、目录、参数、工具、隔离与回归测试全部通过，实际页面手工验证，
并将“文档已核验 / 契约已测试 / 真实调用已验证”分开报告。仍不等于云端安全认证。

## 8. 实施顺序与待审阅决定

顺序：能力注册表与请求/存储契约 → DeepSeek 搜索/抓取适配 → 新记忆快照与界面
→ 共享菜单与双语 → 契约/回归测试 → 浏览器验证 → 经单独预算批准的真实烟测。

本设计选择：内容优先的记忆页；官方目录加账户发现；每型号真实 reasoning；
DeepSeek 独立工具 API；不自动跨服务商搜索；保持现有执行预算和用户凭据边界。
用户审阅这份书面设计后，再形成具体实施计划，不直接修改正在运行的应用。
