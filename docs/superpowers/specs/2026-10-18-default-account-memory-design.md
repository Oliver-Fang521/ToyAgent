# 默认开启、用户可控的账户长期记忆

日期：2026-10-18。状态：用户已确认本书面设计，进入实现计划审阅；尚未开始产品实现。

## 1. 用户意图与验收目标

用户要求沿用现有 LangGraph Agent，增加账户级个性化记忆：新建对话后仍能知道用户明确
表达的普通背景、偏好、项目与目标。最新要求覆盖此前的 opt-in 建议：默认开启，不要求
用户先授权开启，也不逐条弹窗询问；用户随时可以查看、修改、删除、暂停记忆。

“默认开启”不等于隐蔽记录：界面常驻显示状态、用途与管理入口。匿名请求不创建账户记忆。
本需求是网页产品的数据功能，不是修改开发助手的 Codex 个人记忆目录。

成功条件：账户 A 在对话 1 说“我在学 Python，喜欢中文和先举例”，对话 2 的相关回复能
自然采用该背景；账户 B 不会读到这些信息；纠正、删除、暂停后，后续请求遵循用户修改。
不要求每次复述画像，也不能用个人偏好替代事实验证。

## 2. 已检查的代码与方案选择

现有 `ConversationStore.history(owner,cid)` 只取同一对话最近 4 轮完成的问答；
`bounded_history` 再限制为最多 8 条消息、约 6000 字节。历史持久化不等于跨对话记忆。
`UserRuntime` 已有按 owner/provider 隔离的凭据与固定官方端点；新系统不得破坏这些边界。

比较过的路径：

- **推荐：自有 MemoryService + 现有 LangGraph。** 复用当前数据库、认证和模型接口，
  自己控制来源、版本、删除屏障和 UI；首版不增加记忆服务 Key 或外部数据接收方。
- Mem0 OSS 可减少部分抽取/检索代码，但仍需实现用户权限、编辑冲突和删除防复活；
  当前官方 add 文档是新增流程，不假定它自动解决事实替换、合并和遗忘。
- 整体迁移 Letta 会改变已有运行时、工具与验证链路，当前不采用；借鉴其分层上下文思想。

官方参考（前一轮已读取，核对日期 2026-10-18）：

- LangGraph：线程记忆与 namespace 级长期记忆、profile/collection、写入时机。
  https://docs.langchain.com/oss/python/concepts/memory
- Letta：核心 memory blocks 和可检索历史。该链接为 V1 SDK 概念说明，不当作新版 SDK 接口。
  https://docs.letta.com/v1-sdk/concepts/stateful-agents
- Mem0：按用户范围提取事实、偏好与后续检索；明确区分 SDK 管理功能与产品权限职责。
  https://docs.mem0.ai/core-concepts/memory-operations/add

## 3. 默认行为及不做的事

- 已登录账户首次访问采用 `enabled=true` 的服务端默认设置；旧数据库按缺省值解释，
  不需要逐个账户创建虚假授权记录。用户关闭后持久保存 false，不因刷新/重启重新开启。
- 只处理功能启用后新提交的用户文本；不自动扫描旧聊天、附件或服务器文件。
- 暂停状态同时停止检索与自动写入，但不删除已有内容；恢复后不补处理暂停期间的文本。
- 每条请求可选 `memory_mode=temporary`：既不读取也不写入长期记忆。
  UI 必须说明临时模式不等于“不保存普通聊天记录”；两者是不同功能。
- 不新增 Mem0 Cloud、外部 embedding 服务、向量数据库、时序知识图谱或模型训练。
- 不更换模型、不使用站长 Key，不开启额外付费后台定时任务，不改 GAIA/CLI 行为。

## 4. 记忆类型、来源与可信度

| 类别 | 内容 | 例子与限制 |
| --- | --- | --- |
| profile | 普通背景、语言和表达偏好、技能经验 | “正在学习 Python”“希望先举例”；不推断年龄、性别或健康状态 |
| project | 用户明确描述的项目、目标与当前约束 | “Project Northstar 使用 SQLite”；不从模型建议自动认定用户已决定采用 |
| decision | 用户明确陈述的重要经历、选择、纠正 | “我决定先完成 MVP”；不能把助手自称完成的动作写成用户经历 |

自动写入只接收当前用户文本中可定位的自述。抽取候选必须含精确来源片段及字符位置，
服务端校验其属于本次 owner 的当前请求。引用、第三人称材料、角色扮演、假设和问题中的
示例不当作自述；含混时不保存。模型输出、网页、工具结果和上传内容不能直接写入画像。
“好的”“继续”等文本不得借机从旧历史重新提取已删除事实。

Key、密码、令牌、验证码、私钥与认证信息永不入库，也不能出现在候选日志中。
默认不自动记录健康、宗教、政治、性取向、精确住址、政府证件或财务账户等敏感内容。
首版管理页同样拒绝凭据和敏感身份档案；不是要求用户给这些信息逐条授权，而是不收集。
人工编辑的普通信息优先于模型推测；当前用户指令优先于旧记忆。

## 5. 数据与模块边界

新增独立 memory 模块，避免把全部职责堆进现有 store/runtime：

- `MemoryRepository`：owner 范围的 SQLite CRUD、乐观版本锁、事务、删除与清空屏障。
- `MemoryExtractor`：使用当前选定 provider/model 的严格结构化、无工具调用抽取候选；
  不持有另一个服务商的 Key，不可直接执行数据库操作。
- `MemoryPolicy`：来源校验、敏感信息拒绝、字段规范化、版本替换和重学限制。
- `MemoryRetriever`：在权限过滤后的当前有效条目中做有界筛选，返回引用 ID 和文本预算。
- `MemoryService`：协调检索/写入、账户开关与修改屏障，提供给已有公开运行时。
- 前端 `MemorySettings`：状态、列表、编辑、删除、清空、暂停及共享范围。

条目包括：`id, owner, category, canonical_key, revision, origin_provider,
allowed_providers, status, source_run_id, source_offsets, created_at, updated_at,
last_confirmed_at, expires_at, edited_by_user`。公开响应不暴露 owner、加密包或内部文件路径。
对外 owner 始终来自现有受信认证链，不接收客户端自报 owner。

正文和必要来源片段使用基础设施密钥加密，AAD 使用独立 memory 域加 owner/id/version，
不能直接复用 credential 的 provider AAD 格式。元数据只保留运行所需字段。
数据库中的 canonical_key 是 owner 范围的规范键 HMAC，不保存可读的项目名称或个人属性值；
可读语义键位于加密正文。服务端使用受控背景字段与稳定项目键，而不是信任模型任意换标签。
不得建立包含完整画像的明文 FTS 索引；首版在账户有界候选上解密后做内存内检索。

每个账户最多 200 条 active 记忆，每条正文最多 500 字符，每轮自动候选最多 5 条。
满额时不静默删除人工编辑内容，跳过新增并显示可管理提示。

## 6. 检索与跨服务商范围

先在数据库侧过滤 owner、状态、有效期和允许的 provider，再读取文本，禁止全库检索后
才在模型输出中做权限过滤。检索预算最多 8 条、6000 UTF-8 字节；优先小型背景/偏好，
项目和决定按当前问题的关联度、近期确认和来源质量选择，不把所有对话拼入提示。

首版使用结构化字段匹配、词项与中文字符片段匹配，不声称具备完整语义向量召回；后续
只有评测证明遗漏影响体验时才增加本地 embedding 或其他服务，并单独讨论依赖及费用。

记忆作为有来源的“不受信用户上下文”注入理解问题和需要个性化的执行节点，不能提升为
system 指令，不能改变安全策略、工具预算或验证规则；不能把个人记忆包装成网页证据。

同账户、同服务商跨对话默认共享。保留先前确认的数据接收边界：跨 OpenAI/DeepSeek
默认隔离；用户可在记忆管理页修改具体条目的服务商可用范围，不每次弹窗。
选择新服务商不自动复制另一家的历史或个人记忆。此处是保守设计边界，书面审阅可调整。

## 7. 写入、纠错、遗忘及并发

先生成正常回答，再尝试一次有界记忆抽取/合并；记忆故障不能把成功回答改成失败。
自动候选只来自本次用户文本以及权限允许、与候选有关的当前记忆，不输入完整旧聊天。
抽取前先做敏感字段拒绝/遮蔽；日志仅记录状态、计数和安全失败码，不记录输入与候选正文。
抽取最多一次逻辑模型请求、最多 800 输出 tokens、8 秒，并受现有 500 秒总截止时间限制；
剩余时间不足时跳过。无工具、无隐藏推理持久化，失败不自动重试或切换服务商。

本次抽取使用用户当前模型凭据，额外 usage 纳入本任务统计；UI 明示记忆整理可能有模型
费用，不新增搜索/记忆 API Key。客户端关闭后不偷偷启动新的付费任务。
回答界面可显示“记住了 N 项”或“本次未更新记忆”，并提供查看/撤销入口。

已有 canonical_key 的明确纠正采用版本替换，旧版本变为 superseded，只检索当前有效版本。
用户手工编辑使用 revision/If-Match，过时修改返回 409 而非覆盖；来源不足或模型与手工编辑
冲突时保留手工值，不静默改掉。暂时性项目/决定支持 expires_at，过期不再用于回答。
普通长期偏好不按最后一次访问强制失效；时效性背景保留确认日期，不把旧职业/地点当作
实时事实作重要判断。检索不算用户重新确认。

删除会去除在线正文、来源片段和派生索引，并保留不含原文的规范键 HMAC/tombstone。
模型不能因为同义写法、旧摘要或旧对话再次提取而绕过该屏障。重新保存已删除项只能由
用户在管理页明确新增，或本次明确要求“重新记住”，不能仅依赖旧文本。
清空记录 capture 水位并建立防复活屏障，不回扫旧记录；“清空”与“暂停”是两个动作。

更新/删除/暂停/共享范围变化增加 memory generation。复用已有 owner 任务取消屏障，
撤销在途/排队任务的旧 memory snapshot，等待取消后返回；派发和每个新模型阶段均检查
generation，防止已删除记忆继续注入。管理页说明修改会中止当前任务、已发送请求无法撤回。
不更改用户凭据，不自动重新提交被取消的任务。

SQLite 在线删除不承诺擦除进程内存、WAL 或备份；恢复备份不得把已删记忆重新设为可用。
实际平台快照保留和删除验证仍是发布门槛，不能用数据库 tombstone 冒充已完成物理删除。

## 8. API 与界面

全部管理接口需要现有身份验证、同源变更检查和后端服务令牌：

- `GET /v1/memory/settings`：enabled、版本与说明。
- `POST /v1/memory/settings`：开关，缺省账户为开启；临时请求不改账户开关。
- `GET /v1/memories`：仅本人条目、来源时间、类别与可用服务商，分页且不缓存。
- `POST /v1/memories`：人工新增普通记忆，经过同一安全策略。
- `POST /v1/memories/{id}/update`：编辑正文、有效期、允许服务商，必须携带 revision。
- `POST /v1/memories/{id}/delete`、`POST /v1/memories/clear`：带防复活屏障的删除。

维持现有 GET/POST 代理风格，新增路由必须加入严格 allowlist，匿名目录例外不能扩展到记忆。
运行结果只新增简短 memory 状态与引用 ID，不把画像放进 progress、错误、公共日志或 tracing。
账户页面可读具体记忆正文，不提供管理员跨账户读取功能。

输入区可见“长期记忆已开启 / 已暂停 / 临时对话”，不是授权弹窗。管理界面支持键盘和窄屏，
清楚区别“删除聊天”“删除记忆”“暂停记忆”；删除和撤销结果可验证，不自动发送用户问题。
记忆服务不可用时正常回复并显示降级状态，不伪称已保存；缺少模型 Key 时不做抽取，也不
借用站长 Key。人工 CRUD 不需要模型 Key，关闭/删除记忆不应被 Key 缺失阻挡。

## 9. 验证与交付门槛

采用 TDD，至少覆盖：

1. 新旧账户默认开启、关闭持久化、匿名无画像、无来源旧聊天不回填。
2. 跨对话相关背景召回、无关条目不塞入、当前指令覆盖旧偏好。
3. 跨账户拒绝、跨 provider 默认隔离、修改共享范围后才可用于对应服务商。
4. 用户纠正替换旧值、人工编辑优先、过时 revision 冲突、并发结果不丢更新。
5. 删除后旧消息/同义候选/旧摘要不复活，清空/暂停/临时模式不自动补采。
6. Key/密码和敏感信息拒绝；网页注入、附件、角色扮演、助手幻觉不写画像。
7. 抽取超时/格式错/数据库错/Key 失效仍返回原回答；usage 纳入预算且不重复抽取计费。
8. 删除/编辑与排队或活动任务竞争时旧 snapshot 不再派发；无自动付费重试。
9. 后端重启后记忆和用户开关有效，tombstone 不丢；日志、数据库明文与 UI 错误无秘密。
10. UI 状态、编辑/撤销/删除/清空、窄屏/键盘、暂停与临时模式的可观察结果。

复跑完整 Python、Ruff、前端 Node、TypeScript 和构建；真实托管认证及备份恢复仍需独立验证。
此前六个付费 smoke 任务的授权已用完。本功能不复用该限额，不从聊天抄 Key 开始新实测；
完成离线检查后应列出新的具体测试任务数和费用承担方式，再取得付费测试许可。

## 10. 当前阶段与范围控制

本次只提交设计，不创建真实用户记忆、不回填用户信息、不修改运行中的默认行为。
用户审阅本文后，再编写实现计划；仍沿用既有 inline/no-subagent 工作方式。
不在此功能中同时接入 Tavily、改搜索计费、推送 PR 或部署。

设计自查：账户与服务商范围明确；默认开启与可暂停不矛盾；删除屏障不含原文；
人工 CRUD 不依赖模型 Key；自动提取有时间/费用预算，失败不阻断回答；
首版词项检索不冒称语义记忆 SOTA，接口保留以后替换检索器的边界。
