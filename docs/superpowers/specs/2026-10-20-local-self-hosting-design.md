# ToyAgent 单用户本地自部署设计

## 目标与边界

让其他人克隆仓库后，安装 Docker Compose 即可在自己的电脑运行完整 ToyAgent：初始化本地密码、启动、登录、填写自己的 OpenAI/DeepSeek Key、聊天与管理记忆。无需 Sites、ChatGPT 登录或作者凭据。

首版只支持一个本地账户、单后端实例、loopback HTTP。不是公网多用户部署方案，不增加注册、邮件、密码找回或托管发布。现有 Sites 模式与身份信任边界保持不变。不会把本机现有聊天、Key、runtime.env 或测试夹具打包到镜像。

## 架构与启动

Compose 提供 frontend、backend 两个长期服务与显式运行的 init 工具。只映射 frontend 的 `127.0.0.1:3000`；backend 不发布宿主端口。前端代理通过 Compose 内部网络访问后端，继续使用服务令牌及服务端绑定的 owner。网络允许后端访问官方模型与网页工具，不误设为禁止外网的 internal 网络。

提供根目录 Compose、严格的 Docker build ignore、多阶段 Node 前端镜像、Python 后端镜像，以及不含秘密的配置模板。使用现有 lockfile 安装依赖；构建后不运行 dev server。Node 使用项目支持的版本，Python 使用 3.12。容器以非 root 用户运行，明确数据卷权限；init 仅完成初始化和权限设置后退出。单实例 SQLite，不扩容副本。

预期流程：复制配置模板（仅非敏感端口等选项）；`docker compose run --rm init` 交互输入并确认访问密码；`docker compose up -d --build`；打开 localhost。init 必须具备 TTY，密码不经命令行、环境变量、日志或 shell history。缺少初始化时服务以明确配置错误失败，不生成临时加密密钥。

## 独立身份与会话

通过显式服务端 `AGENT_AUTH_MODE=local` 启用本地认证，默认仍为 Sites。建立小型身份解析层，将首页与代理使用的身份解析统一；local 模式完全忽略浏览器提交的 oai 身份头，Sites 模式不接受本地 cookie。客户端不能选择认证模式。

init 创建随机稳定 owner ID、服务令牌、加密 keyring、会话签名密钥与带盐 scrypt 密码摘要。密码摘要格式固定参数并设资源上限；登录由 Node 服务端验证，不记录密码。配置格式与解析有版本及校验，不凭任意字段创建身份。

本地登录页支持中英文，隐藏 ChatGPT 品牌登录提示。成功登录设置签名的 HttpOnly、SameSite=Strict、Path=/、固定 12 小时过期 host-only cookie；loopback HTTP 下不设置 Secure，文档明确不可用于公网。随机会话 nonce，验证签名及到期时间；不把密码摘要或服务令牌放入 cookie。所有身份页面和响应禁止缓存。

登录、退出均为 POST，要求合法同源 Origin 和受限请求体；拒绝异常 Host，允许的 localhost/127.0.0.1 origin 与配置端口严格匹配。失败文案统一，不输出底层异常。登录设置有界的失败尝试限制与 Retry-After（单前端实例内存限制，重启会重置）；不接受 X-Forwarded-For 绕过。返回地址仅允许安全本站相对路径。退出清除 cookie；重置密码通过停止服务后的本地维护命令，轮换签名密钥使全部旧会话失效，不改变 owner 或数据加密密钥。

现有代理的同源写入校验、固定路径白名单、身份重写与跨站限制继续生效。后端令牌校验及 owner 绑定不放宽。伪造 cookie、浏览器身份头、跨站请求不能访问聊天/Key/记忆接口。

## 配置、存储和升级

独立命名卷保存运行秘密与业务数据。前端仅挂载密码摘要、owner、会话密钥与服务令牌，不获得记忆加密主密钥；后端仅获得其服务令牌和加密 keyring，不获得访问密码摘要/会话密钥。init 写入分服务目录，运行服务只读挂载各自秘密目录。entrypoint 只加载明确允许字段，不 source 用户提供的 shell 文件，不打印秘密。

重复 init 默认拒绝覆盖已有状态，不在损坏/部分初始化时悄悄换主密钥。初始化采用临时写入、验证及完成标记，失败给出恢复方向；任何已有密钥不自动替换。数据卷包含原有 SQLite、上传与工作目录；`down` 不删除，文档明显警告 `down -v` 会破坏数据。

提供停止服务后的一致性离线备份与恢复流程，备份必须同时保留业务卷和秘密卷，包含 tombstone 与历史 keyring；备份本身敏感。恢复到空实例，禁止合并覆盖活跃数据。升级采用重新构建/启动，先备份，不承诺未经验证的任意版本降级。README 给出启动、日志、停止、升级、密码重置、备份、故障排查入口。

## 验证与完成标准

先用回归测试覆盖认证模式隔离、scrypt 密码匹配/错误、cookie 伪造/到期、Origin/Host/redirect、限速与退出、代理身份不可伪造、初始化幂等拒绝与不泄漏、权限和秘密分离。保持现有前后端测试通过；对登录的安全与易用性都做浏览器检查。

执行 `docker compose config`、两个镜像构建及全新卷启动：登录、匿名 API 拒绝、填写合成 Key、合成数据持久化、重启后保留、退出后拒绝、密码重置后旧 cookie 失效、停止后备份恢复。合成模式只能由测试工具启用，不植入生产身份或默认假执行器。真实付费调用不属于本轮自动验收。

如 Docker daemon 不可用，清楚记录未验证的镜像构建/容器启动项，不把静态配置或宿主启动称为 Compose 实测成功，不修改现有服务替代验收。现有用户数据和正在运行的服务不用于破坏性测试。

## 设计自检

认证模式仅服务端选择；密钥不进入镜像/仓库；单账户 owner 稳定；既有模型/记忆业务接口保持；密码重置不破坏数据解密；仅 loopback 不作公网安全承诺。实现前需用户审阅本设计，再编写实施计划。
