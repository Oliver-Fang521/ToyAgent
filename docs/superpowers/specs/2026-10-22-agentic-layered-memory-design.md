# ToyAgent 模型驱动的分层记忆与循环检索

日期：2026-10-22（America/Chicago）。状态：对话方向已确认，本文待用户审阅；不是实施完成报告。

## 1. 目标、范围与已有设计的关系

用户要求取消长期记忆保存条数限制，参考 Codex：由当前主模型决定是否查记忆、读哪些内容及是否继续读取；后台由模型增量整理、归纳和压缩，不能用固定关键词或 Python 预选的八条事实替代主模型的读取决策。记忆应跨对话帮助回答，同时允许用户查看、修改、普通删除、永久遗忘、暂停及临时模式；不恢复每轮记忆更新提醒。

采用已有加密 SQLite、用户自有凭据和研究验证框架，新增可重建派生摘要、全库索引和只读记忆工具。不迁移到明文文件、不引入第三方记忆 SaaS、embedding 服务或单独的“是否查记忆”分类模型。用户选择的当前任务模型承担检索决策；后台整理用产生相关变更时记录的用户模型/provider/reasoning，绝不静默改成平台模型或使用作者 Key。

本设计覆盖旧设计中“200 条保存/候选上限”和“Python 预选八条后注入”的部分；旧有来源校验、加密、手动编辑优先、普通删除与永久遗忘区别、凭据撤销、付费派发日志仍有效。不要把本设计当成对旧数据进行批量付费处理或更新真实实例的授权。

方案比较：仅删除上限不能解决旧事实召回；照搬 Codex 本地 Markdown/Git 记忆不适合隔离账户；选择数据库内的概要—主题—事实结构，借鉴其渐进读取与增量整理。这里的模型归纳不是无损压缩，不承诺概要包含全部事实。

## 2. 当前代码基线

基线提交 `1c4fc19`。`memory/repository.py` 拒绝第 201 条新增，`list_snapshot` 与 `eligible` 也只取最近 200 条。`memory/retrieval.py` 用词法匹配最多选择八条/6000 UTF-8 bytes；`memory/projections.py` 是主题和来源指针缓存，不是真正的模型概要。`routing.py` 当前入口为 tool-free，直接生成 direct/research/clarify 决策。`memory/worker.py` 已有持久任务、两个后台消费者、用户模型提取及确定性合并检查。

本轮改变读取与整理，不重写事实捕获的全部语义：继续以完成任务中的当前用户陈述为主要来源。整段历史回扫、长消息提取超过五项的独立优化、不可信网页/附件自动转画像均不在本轮范围。明确说明这一边界，不能声称已完整复现 Codex 的 rollout extraction。

## 3. 三层数据与事实权威

### 3.1 事实层

已发布的规范记忆是权威来源，保留 ID、修订号、来源、主题/实体、用户编辑标志、provider 权限及加密内容。取消按账户固定条数的写入拒绝；不改成更大的隐藏固定上限。单条内容长度、请求体、磁盘/数据库异常和单次工作预算仍有限，相关错误必须准确显示，不假称物理存储无限。

不因年龄、少用或摘要压缩自动淘汰有效事实；用户纠正、显式过期、撤销和删除按既有规则改变有效性。保留最小可追溯来源，不延长秘密、已删除内容或记忆输入任务载荷的留存。已退休的源消息不从真实聊天回填；来源不可用时工具只返回仍合法保留的证据片段和安全指针，不擅自读取整段聊天。

### 3.2 主题摘要层

新增加密主题摘要：账户、provider 域、opaque 主题 ID、输入事实 ID/revision 依赖集、内容指纹、生成模型与提示词版本、更新时间和状态。每个摘要结论必须引用实际提供的有效事实；模型可合并表达和归纳共同偏好，但不把讨论升级成决定、不扩大实体作用域、不覆盖手动事实。

大主题按有界事实批次生成分片摘要，再由模型合并为主题摘要。未被摘要覆盖的事实仍可检索。依赖关系允许程序发现删改并令派生文本失效；不能仅检查“引用 ID 存在”就宣称语义忠实，真实模型测试还要检验歪曲、遗漏和过度概括。

### 3.3 账户概要层

由模型根据当前有效主题摘要生成紧凑的用户基础背景与导航；包含可读主题线索、opaque 引用及覆盖状态。概要不能成为无限追加的总笔记。超过预算时优先保留稳定基础背景及主题导航，详细事实留在工具中。

概要不覆盖所有主题，也不承担唯一搜索入口；即使旧主题不在概要，搜索工具仍能从完整事实库找到它。某个输入主题失效时，依赖它的概要立即失效；没有当前概要时只给读取规则与 `summary_pending/unavailable` 状态，不回退到注入八条关键词事实，也不等待后台模型完成才允许聊天。

## 4. 后台模型整理与压缩

每次规范事实新增、更新、删除或权限变化，以确定性依赖映射标脏相关主题及概要；归类/合并建议由模型作出，发布权限由服务端决定。模型提出稳定的主题映射，程序只接受本账户提供过的事实/主题 ID；模糊匹配或未知 ID 不改变无关数据。普通变更只使相关主题失效，不让所有事实重算。

同一账户/provider 的相同变更范围合并排队；每个范围只允许一个有效整理租约。按批次处理整个脏范围，持久化游标和输入修订，不只处理最近 N 条。摘要、索引、任务元数据都使用账户域加密/opaque ID；每轮日志只记阶段、用量和安全失败码。

整理请求为严格结构化输出，包含摘要片段与依据 ID/revision。服务端检查账户/provider、引用有效性、内容安全、输入版本和预算；用 CAS 原子发布。输入中途改变则丢弃过时建议并保留脏标记，不能发布旧摘要。成功后的用户事实不会因摘要失败回滚。

沿用付费派发日志和凭据 epoch：不自动重发已经派发但结果不确定的调用；超时、撤销、余额/用量不足记录真实状态。新变更可创建新的版本任务，不能成为重复付费旧任务的借口。已有失败摘要重试须显式触发且限一次；系统故障不能造成无人值守的重试费用循环。

工程初值：同一域变更至少合并等待 10 秒，后台沿用全局最多两个消费者；单域每小时最多四次整理调用、每次最多 30 秒、最多 1000 输出 tokens。额度是整理工作预算，不是事实保存限制；超出后保留脏任务和全部事实，后续窗口继续未派发批次。概要与主题调用均计入该额度，不为概要另设不受控调用。旧库迁移只建确定性索引；模型批量整理旧库须用户显式启动并单独批准费用范围。token 用量累计，但价格未知时不承诺美元硬限。

## 5. 主模型驱动的读取循环

### 5.1 首次输入与动作

入口请求携带当前问题、允许的对话上下文、可信记忆使用规则、状态以及有界账户概要。概要与事实明确标为不可信用户数据，不能提升为系统指令，也不能改变研究/安全验证要求。暂停或临时模式不注入内容、不开放读取工具，且沿用不写入规则。

不增加独立的记忆分类器。扩展入口主模型的结构化决策，使其在原 direct/research/clarify 外，可以请求记忆工具。每次模型响应要么提出受限只读工具动作，要么给出原路由决定；服务器验证 schema，不执行任意函数、SQL、文件路径或 URL。不要求展示/保存模型隐藏推理，只记录动作、引用和安全状态。

### 5.2 只读工具契约

- `search_memory(query, cursor?, limit?)`：搜索本账户当前 provider 可见的全部有效主题与事实。返回有界片段、ID、revision、匹配类型、覆盖/截断状态、后续游标。概要不存在也可用。
- `read_memory(kind, ids)`：按 opaque ID 读取主题摘要、事实或合法来源证据，返回当前版本、引用及状态；主题可返回分页事实指针。不能通过此接口读取任意聊天、文件、其他账户或未获准 provider 的内容。

owner/provider 由服务器绑定，不接受模型指定。每次读取和发给模型前重新检查 generation/权限与依赖；删除或暂停后取消受影响的活动任务，不能重新注入本地已缓存文本。已发送给服务商的数据无法收回，不宣称删除能追溯撤回。

### 5.3 循环与退出

模型看到工具结果后再次选择继续搜索、展开主题、读证据、澄清或结束读取；可以改写同义查询，不设置“只读一轮”。新文本进入同一动作循环，不能丢掉上一轮结果后从头分类。服务端工具不额外调用一个模型判断是否足够。

初值：最多六轮工具请求、累计八次工具执行，包含最后一次决策在内最多七次主模型调用。账户概要最多 1200 UTF-8 bytes；单次工具结果最多 4000 bytes；累计记忆载荷（概要、结果和指针）最多 16000 bytes，并同时服从模型实际输入 token 与现有任务截止时间的更小预算。预算不是召回事实总数限制。无记忆工具动作时仍只需原有一次路由调用。

最后允许的一次模型请求禁用工具；因预算结束时让模型依据已有证据回答/澄清/转现场验证。若最终请求也失败，返回安全且真实的错误，不附加一次“修复分类”调用。结构非法、未知工具不能绕过循环次数或触发免费无限重试。

相同规范化工具参数且没有新版本/新游标的重复读取，不重复计费派发，返回 `no_new_information`；连续两轮无新增证据即停止检索。空结果是 `not_found_in_search`，不是事实不存在。预算耗尽、索引未完成、部分失败和来源缺失显式返回覆盖状态。模型不得因截断而声称已查全；必要时说明缺口或问一个澄清问题。

本循环主要帮助对话入口找齐背景。结束后，direct 使用已有上下文回答；research 把同一有效记忆包/引用传入既有研究与验证流程，不能丢弃刚读到的记忆，也不能当作外部事实证据。后续研究节点本轮不再建立另一个独立六轮记忆循环。整个研究 Agent 仍可能因研究工具而产生更多模型调用，不能把七次说成任务总上限。

## 6. 全库检索而非最近两百条

为事实和主题建立账户域 HMAC 词项到 opaque ID 的倒排索引；索引无明文内容，仅作为派生候选。中文双字/英文词项是基础词法索引，不冒称向量语义检索。主模型可以拆分实体、改写同义词并多轮搜索；无词项命中时提供主题导航分页，而不是全库任意猜测。

查询内候选排序和有界返回可以限制工作量，但必须提供 continuation/覆盖状态，使相关老事实可经分页访问，不能只取全库最近 N 条后做相关性计算。大量候选分批解密筛选，避免全库解密到内存。HMAC 词项仍可能暴露账户内频率/关联，不承诺等同于无泄露索引。

用户管理页使用服务端搜索与分页，返回总数/游标；删除“200 条满了”的产品提示。旧客户端保留分页兼容，新字段加版本，不让兼容接口一次返回无界列表。原 `list_snapshot` 不能简单删掉 LIMIT 后把全库塞入一次请求；拆成小状态快照和可分页事实读取。提取器所需已有候选同样走全库索引的有界匹配，不能继续隐藏最近两百条截断。

## 7. 用户控制、一致性与故障

保持既有新增/编辑/普通删除/永久遗忘/清空/暂停与临时模式语义。普通删除不关闭自动学习，未来新用户消息可重学但不回扫旧消息；永久遗忘保留最小范围屏障，禁止从摘要、旧整理建议或缓存复活。clear 水位阻止旧队列回填，其他主题仍能学习。

写事实和失效摘要/索引在同一事务内完成。先失效再重建，不能因为旧摘要更流畅就继续使用。摘要发布时所有递归依赖有效才能激活；混合来源删掉其中一项时先隐藏整份受影响摘要，再重建仍有依据部分。权限收缩需使 provider 派生概要同时失效，撤销 Key 后禁止后台模型调用。

界面不逐轮弹“更新记忆”；只在用户查看记忆状态或当前问题确实受影响时，展示简短双语状态。管理页不增加说明墙。读取循环失败可继续处理不依赖个人记忆的独立任务，但必须标记缺失；不能把错误伪装成无记忆，也不能以关闭事实验证实现降级。

## 8. 组件边界

- 既有 repository/crypto/retention/barriers：规范事实及用户控制，新增派生依赖失效接口。
- `memory/index`：全库账户域候选、分批回填与分页；无模型调用。
- `memory/summaries`：摘要 schema、模型请求、依赖验证、CAS 发布；不修改规范事实。
- `memory/maintenance`：脏范围、合并/工作预算、租约、付费派发账本；复用现有队列安全规则但不混淆提取与整理任务。
- `memory/tools` 与读取循环：服务端只读契约、主模型动作、证据/预算/重复检测。
- routing/credential runtime/composition：一次会话的循环接入及 direct/research 上下文交接。
- API/管理页：分页搜索和简短状态；不接受客户端自报 owner。

文件名在实施计划落定；以上是职责契约，不要求创建所有同名目录。避免再把所有逻辑堆进 repository 或 worker。

## 9. 迁移与验收

采用加法、幂等迁移，保留旧事实 ID、revision、provider mask、遗忘屏障及加密版本。先备份，不重建用户凭据、不清空数据。确定性索引回填逐批可恢复；回填未完成时继续分批查旧记录并标 `index_pending`，不能把未索引记录当不存在。移除容量限制与新检索/分页同时上线，不能只改写入。

按 RED→GREEN 覆盖以下验收：

1. 同一账户至少 1000 条独立事实都能保存，旧事实不被新事实挤走；直接 ID 读取及分页全量可达。10,000 条合成数据测量索引构建、候选查询、解密数量、内存和端到端延迟，报告实测值而非预设“无限扩展”。
2. 200 条以前的老事实、概要未列主题、中文/英文改写、多实体同名、错别字和同义查询；分别报告词法未命中与模型改写后召回，不用修改断言掩盖漏召回。
3. 同一主模型零工具直接答、一轮搜索结束、多轮搜索→读主题→读来源→答；断言调用次数、主模型/provider 和上下文连续性，无额外分类模型。
4. 模型发现不够继续查；重复、空结果、截断、六轮/八工具/字节/token/截止时间终止；不得断言事实不存在或虚构已查全。
5. 模型整理包含重复表达、相互独立偏好、明确纠正、不同实体和不确定结论；人工标注合成预期验证归纳忠实度与来源覆盖。摘要错误不得更改原子事实，失败后工具仍能查事实。
6. 暂停、临时模式、跨账户/provider、伪造 ID、摘要提示注入、秘密及日志泄露；模型文本不得授权绕过服务端权限。
7. 在生成、发布和读取各阶段并发修改/删除/永久遗忘/清空；旧依赖不发布、不继续注入，不能从已准备建议复活。
8. 整理超时、崩溃、队列重启、凭据轮换、余额不足、CAS 冲突、输入过大；确认不自动重复付费，事实写入不被可选整理故障阻断。
9. 独立 Docker 旧库升级、幂等索引回填、重启、备份恢复；Python/前端回归及窄屏双语管理分页。未获单独授权不改真实 3025/3000 数据或重启用户运行实例。

离线模型脚本先验证动作契约和确定性边界；真实 OpenAI/DeepSeek 用独立合成账户及事先确定的调用/费用范围验证效果，统计提取、整理和主模型循环用量，不能沿用旧测试通过率冒充新版验收。

## 10. 自检与交接

本设计明确区分：事实保存无限制条数不等于无限资源；模型摘要不等于事实源；词法索引不等于语义向量；模型判断信息足够不等于完整性证明。去除固定容量与改造读取一起交付，禁止悄悄退回八条事实注入。

设计自检：无占位项；保留用户修改/永久遗忘语义；模型负责整理和读取决策，程序负责权限/失效/预算；上下文不足有可观察退出路径。本文审阅通过后再编写实施计划，由用户选择执行方式；当前没有产品代码修改、付费测试、上线或真实数据迁移。
