# ToyAgent 可扩展长期记忆与明确保存指令

## 已确认的目标

记忆不局限于当前固定字段。系统默认从当前用户消息识别值得长期保留的普通背景、偏好、经历、项目、目标和决定；用户不必每次说“请记住”。用户明确要求保存时优先执行，不因字段不在白名单就静默忽略。只在确认写入后反馈成功，失败、暂停、临时模式、容量限制和信息含糊都必须如实反馈。自动更新不恢复每轮对话的记忆提醒。

实际问题：3025 实例中用户提供姓名后跨对话无法回忆；开关开启、数据库零条、提取报告 unchanged/零候选。当前 extraction.py 和 policy.py 只允许有限 facets，前端编辑器也复制了白名单。修复目标是完整业务流程，不只添加姓名字段。

## 方案选择

选择沿用当前加密 SQLite、账户隔离和 LangGraph 流程，增加可扩展语义主题及明确记忆事务。继续追加固定字段无法覆盖用户需求；整体迁移第三方记忆平台则增加外部数据流和运维成本，本轮不做。暂不引入 embedding 服务或额外 API Key；“语义”指模型理解信息及合并关系，不把词法检索改名为向量检索。

2026-10-21 按用户要求参考 Codex 固定提交 `430a16799d90e296fb27b1e94f206023902b7e56`，详见[源码研究](../reports/2026-10-21-codex-memory-source-study.md)。借鉴异步提取/增量整合、来源与概要分层、用户修正优先和按需追溯；不照搬其本地明文文件或高优先级提示注入。源码有 v1/v2 两套格式，不能将 v1 的 MEMORY.md 布局说成唯一实现。

用户最新修正：不要求保存完成后立刻确认。因此明确记忆与自动记忆都采用异步发布，不阻塞正常回答；这覆盖此前“先保存再确认”的同步流程要求，但不允许在未保存时声称成功。

## 参考 Codex 的分层与增量机制

区分三层：①带来源/意图/状态的记忆输入事件；②已验证并发布的规范长期记录；③从记录生成的紧凑概要与主题索引。事件、记录和派生内容均按账户/provider权限隔离并加密；不新增明文 raw_memories.md 或共享 memory 文件夹。保留安全的来源指针，不复制秘密或隐藏推理。

Phase1 从新完成轮次的当前用户消息提取有依据的候选，识别明确指令，不靠关键词或固定 facet。Phase2 对本账户候选与已有记录做去重、更正、追加、遗忘及来源整理，再由服务端校验提交。可复用 Codex 的逻辑分阶段，不强制每条消息都调用两个模型或引入独立多 Agent 框架。

规范记录是事实源，概要只是派生视图，不能覆盖原记录。更正、删除、永久遗忘、暂停或权限变化时立即失效相关概要；未重新生成时从当前规范记录有界渲染，不能继续注入旧概要。摘要使用 owner/provider/generation/revision 键；来源被撤销时同步剔除依赖它的派生结论，有其他独立来源则仅移除失效部分。

长期背景与任务经验分开：用户陈述可以支持画像；当前任务的实际验证只支持该项目经验，不证明用户个人身份或永久偏好。仅在当前任务有真实验证、可复用且符合保存政策时保留安全项目经验；一次讨论或模型提议不自动升级为用户决定。没有有用信息可以 no-op，但明确保存不能因“价值不高”被静默丢弃。

## 信息模型与旧数据

保留 profile/project/decision 三个粗分类作为显示和组织方式，但不再把 facet 枚举作为可保存内容的边界。增加 topic 标签、稳定 slot_id、单值/集合语义、来源类型 automatic/explicit/manual、可追踪来源和更新时间。主题可涵盖称呼、学习背景、兴趣、偏好、持续工作、事件与用户指定备注。

内容继续加密；语义主题、实体和规范键等可读信息也加密，只索引账户域 HMAC/opaque ID。模型只能引用服务端提供的本账户候选 ID，不能发明目标记录 ID。新增标签有长度/格式/数量限制，不把任意自由文本当 SQL、路径或系统指令。

旧记录通过向后兼容的版本化 payload 读取，原 ID/revision、provider mask、主密钥版本及 tombstone 保留；旧 facet 作为初始 topic，不清空数据库或回扫历史。迁移必须幂等，先备份，并在真实 Python 3.12 容器验证。任何新增列需要默认值和兼容旧记录，不能依赖重新初始化用户实例。

## 判断与持久化流程

模型分类输出 none/automatic/explicit/clarify，最多拆成 5 条原子候选。明确保存不依赖第一人称正则：例如“记住：这个项目的截止日期是周五”也应进入 explicit。明确请求支持普通非画像备注，但“记住怎么制作某物”等普通提问不能仅因出现“记住”就当保存指令。

explicit 必须由接入模型根据整条消息的语义判断，不以是否出现“请记住”或固定关键词作为必要条件，也不以命中关键词作为充分条件。例如“以后叫我小林”“这个偏好以后都按这个来”“帮我记下来，下次还要用”“别忘了，我现在学的是数学”“Save this for future conversations”都应识别为明确保留意图。输入预筛选不得先把无关键词、非第一人称的明确请求丢弃；规则仅负责确定性安全检查，不代替意图理解。

“记得提醒我明天开会”等未来提醒/调度请求与长期记忆区分处理。本轮不新增提醒系统；不能只写一条记忆就声称已安排提醒。意图或目标内容不明确时澄清，明确而超出能力时如实解释；用户同时要求保存与提醒时分别反馈两项实际结果。

自动候选只来自当前用户的直接陈述，附精确原文片段和字符位置；不把网页、附件、assistant 回复、假设、第三方推断自动当用户事实。显式候选可保存用户明确指定的普通备注，仍要求当前消息提供内容；“记住刚才那个”若无法唯一确定引用，先澄清，不凭模型猜测补写来源。无需让用户逐条确认清晰的普通保存请求。

保存前由服务端验证来源、大小、安全、账户、provider 权限、revision、generation、容量和遗忘屏障。LLM 提议不能直接执行任意更新/删除，不改变系统提示、工具预算、研究验证规则或外部事实。

前台持久化本轮输入事件后即可正常回答，记忆提取和整理在后台进行，不等待写入结果，也不强制显示确认。明确保存意图由模型语义判断，进入同一可靠队列的高优先级操作；不会只因不存在固定关键词而漏入队。纯记忆请求不进入外部研究流程。事件提交失败与整理失败须保留安全状态，不能在模型正文里虚构成功。

后台使用持久化 job ID、幂等键、claim租约和有限退避；每账户/provider最多一个整合写者，按源序号和revision提交，旧候选不能覆盖较新更正。生成失败保留待处理/失败原因，不无休止重试或反复计费。暂停、临时模式、Key删除/替换、账户generation变化、provider权限或永久遗忘变化，都在领取及提交时检查；过期临时Key不得以运营者Key或其他provider替代。

后台调用可能产生用户模型费用，需在实施计划中固定并测试每作业调用次数、输出token、时限、队列容量、总并发及预算耗尽行为，且用独立tool/memory usage记录，不能藏进不可见无限任务。用户关闭记忆同时停止未执行作业；已发出的请求不能撤回。研究阶段没有进行任何后台付费调用，后续真实效果验收仍需有界测试预算。

沿用当前选定服务商与模型，不借用运营者 Key；高优先级是保存意图优先处理，不代表跳过网络、存储或安全限制。无 Key 时仍可在管理页手动添加；聊天保存需要模型时沿用配置引导，返回后不自动付费提交。

## 合并、更正和检索

姓名、称呼等单值信息更新同一 slot；“我现在改用……”“之前说错了……”明确更正时新值替代旧值。兴趣、技能等集合拆成独立条目或做可验证的追加，不能新说 Python 就覆盖以前的数学背景。

去重/冲突判断使用账户内相关记录和稳定 slot 引用；服务端 CAS 校验，未知 ID、跨账户 ID 或不明确替换拒绝。手动编辑内容不被自动提取覆盖；明确聊天更正手动值需确认冲突，不能让模型绕过用户修改优先级。

称呼、基础背景等身份查询可取基础画像；其他记忆先读当前有效的小概要/索引，再按当前问题读取相关记录，额外证据可能改变答案时才追溯来源。概要加明细合计仍遵守最多 8 条记录/6000 UTF-8 bytes 预算，不把全部历史或全部 200 条记忆塞入每次模型请求；历史对可变事实不构成当前证明。新对话使用账户记忆，而不是偷偷拼接其他服务商历史。

读取只使用已发布记录。若保存事件仍待处理，尤其直接询问“你记住了吗/我是谁”时，不能把排队当完成，也不能根据 pending 猜测用户身份；必要时简短说明正在整理。需测量完成后跨新对话可用的端到端延迟，不能以异步为理由长期丢失信息。

## 用户控制和删除安全

沿用默认开启、暂停、临时模式、手动编辑、删除、清空、revision409、账户隔离、逐条 provider 共享控制。暂停/临时模式下明确“请记住”也不绕过开关，提示去管理页启用或退出临时模式；不隐式改变设置。

用户已明确选择：任何删除均不改变账户自动学习开关，也不冻结其他主题。普通删除只移除当前记录，不新增永久遗忘屏障；以后新的用户消息再次提供该信息时可重新学习，但不回扫旧聊天重建。管理页默认“删除”为普通删除，不隐含永久语义。

只有用户明确表达永久忘记、不再记住等语义，或在管理页明确选择“永久忘记”，才移除记录并建立该信息范围的持久化遗忘屏障。该意图同样由语义识别，不只匹配“永久删除”字面。解除屏障需要用户明确恢复该信息的意图；不明确的普通重复不能解除。永久遗忘不扩大成整个类别或整个账户的自动学习暂停，不误伤同一项目、技能类别中的其他信息。

遗忘屏障保存必要的加密主题描述/opaque标识及来源水位，不保留已删除的原始内容或其 source fragment。提取/合并阶段将相关屏障提供给模型做语义匹配，服务端校验引用ID、动作权限和generation；疑似匹配不确定时仅跳过或澄清受影响候选，不阻止其他独立候选保存。不能宣称LLM对任意同义表达能提供数学保证；需用跨措辞测试衡量漏匹配与误拦截，失败时不得伪装已实现可靠遗忘。

旧版本已存在的 tombstone 不自动解除或销毁，保留用户原有遗忘保护；clear 水位保留，清空不回填历史，未来新消息仍可自动学习。永久忘记不等同删除普通聊天、备份或服务商已接收的数据，UI在该操作处简短说明，不在每轮回答重复。

密码、API Key、令牌、支付/证件号码等秘密不保存；高敏感内容自动提取拒绝，显式遇到也解释不可保存。普通姓名/昵称不是凭此一律拒绝的敏感身份信息。明确保存包含一条普通信息和一条秘密时只反馈安全的逐项结果，不回显秘密。

## 返回结果与 UI

MemoryReport 增加向后兼容的 intent、operation 结果、安全原因码和可选确认信息，禁止包含 source fragment、完整原始 provider 异常或秘密。旧回答/历史仍能读取，不把旧 unchanged 误显示为保存成功。

默认不推送每轮保存确认或后台更新提醒；明确保存可以简短表示已收到，不强制等待或弹出成功提示。只有后台事务实际成功后，用户查询状态或管理页才能显示已保存；已有相同内容、排队、部分失败、存储不可用、拒绝、澄清和冲突分别准确表达。助手正文出现“我会记住”不能作为持久化成功证据，最终状态由服务端事务决定。

“我的记忆”默认继续显示正文、搜索、新增和操作，不增加说明墙。新增/编辑不强迫用户从穷举字段中挑选；粗分类可选，主题自动或自由填写；高级设置继续折叠。所有新增控件中英双语；用户正文不翻译。

## 验收要求

先覆盖自动/显式意图判定、原文来源、schema 兼容、合并/CAS、失败码、普通删除/永久遗忘区分、generation 取消、provider 隔离及前端确认的失败测试，再实现。不能只检查 mock 返回了候选或数据库增删成功。

完整场景包括：自我介绍→新对话回忆；未列入旧白名单的普通背景；一条消息多项信息；集合追加；明确更正；明确保存非第一人称备注；含糊引用澄清；模型声称记住但实际写入失败；重复保存；暂停/临时模式；容量满；超时；普通删除后新消息可重学而旧历史不回填；永久遗忘后同义改写被拦截、其他主题继续学习；明确恢复；手动值冲突；其他账户和其他服务商不得串用。

保存意图专项验收必须覆盖上文所有中英文正例，以及不含“记住”的改写、仅含关键词的普通提问、否定保存（“这件事别记下来”）、引用/角色扮演和未来提醒反例；检查实际持久化和新对话读取，不能只断言路由分类返回 explicit。

离线契约与可控模型输出测试先验证确定性边界；真实模型端到端需要单独有界预算，覆盖“自动学习”和“显式保存”而不是仅测手动 CRUD。当前阶段不使用用户的真实 Key 或已有记忆做破坏性测试，也不声称未执行的付费验收已通过。Docker 测试用独立项目；更新3025实例前检查任务状态并备份，未经授权不回填用户旧消息。

## 自检与下一阶段

核心取舍已明确：保留框架和加密存储；开放语义主题而非无界注入；参考 Codex 异步提取与增量整合、概要和明细分层读取；用户不需要即时确认；自动学习与显式操作区分；普通删除不新增永久屏障，明确永久遗忘才建立该信息范围的保护，其他自动学习不变。实施计划需覆盖新旧数据兼容、持久队列、费用边界、摘要失效及真实效果验收，不能通过降低断言或只增加提示语交付。
